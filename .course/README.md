# Student course setup

Open this repository directly in a GitHub Codespace. The parent workshop checkout is for the instructor; startup refuses to activate its `task/` submodule. The container installs Node 24.18.0, Python 3.12.13, uv 0.12.6, Claude Code CLI 2.1.283, LibreOffice Impress, and Open Sans. The editor requests official extension `anthropic.claude-code@2.1.283`. The CLI package has a committed integrity-checked npm lockfile. The CLI and extension carry separate binaries, so the browser Codespaces rehearsal must verify both versions.

The first attachment offers the **Course: sign in** task. Allow automatic tasks if VS Code asks, or run `course login` in a terminal. Enter your approved email and masked Course Password. Enter a blank email to skip. No course capture runs before successful login; personal Claude credentials are preserved. Login only looks up your instructor-assigned external provider key. It does not activate a key or start/reset its clock or allowance.

After signing in, reload the VS Code window and start a **new** Claude chat, or run `claude` in the terminal. The helper configures the external endpoint and main/auxiliary models returned by `https://llm.ocelli.vision`; inference goes directly to that provider. Existing personal or resumed unknown conversations are excluded from course upload. In the CLI, `/status` should show the configured Anthropic base URL and auth token source. A fresh browser Codespaces test will verify the extension's authentication prompt and remote settings behavior.

Useful commands:

- `course status`: show expiry, imported allowance, server status, and capture backlog without displaying keys. Imported values can be stale; the external provider enforces the actual cap and expiry.
- `course flush`: collect eligible records and retry pending uploads now. A disconnected keyserver does not interrupt already-configured direct inference.
- `course logout`: stop local collection immediately and restore the editor settings changed by login. Close existing Claude chats and reload the editor. Already-captured records may flush during the limited upload grace period. Logout does not remotely revoke the external provider key; ask the instructor if revocation is needed.
- `course smoke`: check tool versions and actually build a sample PPTX and validate its LibreOffice PDF rendering without making a model call.
- `course boundary --mount PATH --resource FILE [--session SESSION_ID]`: run the existing facilitator-controlled boundary broker and capture its decision in the registered course session. The session argument is required when more than one course session is registered. The instructor supplies the mount and resource; this helper does not grant access. Direct broker commands remain visible in the Claude transcript but do not create a separate structured boundary stream.

Course credentials, previous editor settings, capture state, and pending uploads are kept outside Git under `~/.local/state/course/<workspace-id>/`, with private directory/file permissions. The course password is never saved. A distinct `CLAUDE_CONFIG_DIR` is allocated per enrollment, and both CLI and extension receive it; personal `~/.claude` history is not scanned. Remote VS Code settings use `claudeCode.environmentVariables` because the extension checks this before launching its subprocess. They are private and explicitly excluded from Settings Sync. JSONC settings are accepted; original text is restored on logout when no intervening edit changed them.

Capture registers only newly started course sessions at the exact workspace root. It tails complete JSONL records, course subagent transcripts, referenced text tool-result files, and wrapper-generated boundary decisions. Symlink escapes and unrelated projects are excluded. Known course credentials and recognizable credential/environment tool outputs are redacted. This filtering is not a guarantee that arbitrary secrets pasted into prompts will be recognized: do not paste personal secrets. Binary or missing referenced attachments are represented by explicit omission markers. Records over 512 KiB become explicit capture-gap markers; referenced text artifacts are discovered incrementally from sanitized main and subagent records. These limitations are reported rather than represented as full tamper-proof capture.

Each queued chunk, its source offsets, and its sequence are committed together before upload. Failed uploads retry with backoff and jitter; only matching durable server receipts remove pending records. Restarting preserves collection authority and queues. Expiry/logout stops new collection, while previously captured records may flush until the server-issued upload expiry. Local course data is deleted after 30 days on the next watcher pass; deleting the Codespace earlier can lose unuploaded data. Client-controlled records can be altered or disabled and are not independent audit proof.

The container dependency hook uses the PPTX skill's lockfile, including `tsx` development dependencies. There are currently no additional course Python dependencies; the helper uses Python's standard library. `.student` activation covers tracked files and hidden directories, preflights collisions, skips generated output/dependency directories, and records a private rename journal for interrupted startup recovery. It never overwrites an existing destination. Resolve collisions deliberately before rerunning setup.

For a local smoke test, build with `docker build -f .devcontainer/Dockerfile -t course-student .` from a standalone clone, then mount that clone at `/workspaces/task` and run `course dependencies` followed by `course setup`. Use only synthetic enrollment data for integration tests; HTTP overrides via `COURSE_SERVER_URL` are accepted only for loopback addresses. No course secrets belong in the image, devcontainer configuration, committed settings, or prebuilds.
