# Student course setup

Open this repository directly in a GitHub Codespace. The parent workshop checkout is for the instructor; startup refuses to activate its `task/` submodule. The container installs Node 24.18.0, Python 3.12.13, uv 0.12.6, Claude Code CLI 2.1.283, LibreOffice Impress, and Open Sans. The editor requests official extension `anthropic.claude-code@2.1.283`. The CLI package has a committed integrity-checked npm lockfile. The CLI and extension carry separate binaries, so the browser Codespaces rehearsal must verify both versions.

The first attachment offers the **Course: sign in** task. Allow automatic tasks if VS Code asks, or run `course login` in a terminal. Enter your approved email and masked Course Password. Enter a blank email to skip. No course capture runs before successful login; personal Claude credentials are preserved. Approved students receive the same shared external provider key after course login. Login does not activate the key or change provider settings. The shared key has no per-student allowance in this client; spending limits and provider expiry are controlled externally by the instructor. The displayed course collection cutoff ends local course collection and course CLI access; it is not a claim that the shared provider key expires then.

When the course uses EIP, successful login starts a small adapter inside your Codespace. It translates Claude’s requests for the EIP endpoint and supplies the instructor’s inference credential, EIP gateway credential, and required system name. The terminal CLI and VS Code extension both use the same local adapter address and a separate local token; neither needs the upstream credentials in its editor environment. You do not need to enter API keys or edit headers. The adapter starts only after approved course login.

After signing in, reload the VS Code window and start a **new** Claude chat, or run `claude` in the terminal. The helper uses the course endpoint and main/auxiliary models returned by `https://clm.ocelli.vision`. In EIP mode, the CLI’s `/status` should show an Anthropic base URL beginning with `http://127.0.0.1:` and the local auth token source. The adapter forwards model requests to EIP; the course keyserver handles login and transcript uploads. Native Anthropic enrollments use the provider directly. Existing personal or resumed unknown conversations are excluded from course upload. The browser Codespaces rehearsal must verify the extension’s authentication prompt, remote settings, and a live EIP tool workflow.

The supported EIP profile turns extended thinking off and disables tool search (`MAX_THINKING_TOKENS=0` and `ENABLE_TOOL_SEARCH=false`). Use ordinary Claude tools in this profile, and keep these settings unchanged. Unsupported request features produce an error instead of being silently converted into different behavior. Both the CLI and extension receive this same profile.

Useful commands:

- `course status`: show the course collection cutoff, shared-key mode, server status, and capture backlog without displaying keys. These labels also remain accurate when the keyserver is offline. Shared provider spend and expiry are controlled externally; there is no USD 40 per-student limit. If the instructor uses the supported participant-key mode instead, the command shows that participant’s imported allowance and marks it as potentially stale.
- `course start`: check or restart the EIP adapter at its saved local address and resume authorized capture. Startup and the capture watcher also check the adapter. If it cannot start, model access stops with a recovery message; the helper does not fall back to sending Claude requests directly to EIP. Rerun this command after correcting the problem, or ask the instructor.
- `course flush`: collect eligible records and retry pending uploads now. A disconnected keyserver does not interrupt already-configured model access while the local adapter is running and the course window remains open.
- `course logout`: stop local collection, remove the adapter’s private configuration, shut down the adapter, and restore the editor settings changed by login. Close existing Claude chats and reload the editor. Already-captured records may flush during the limited upload grace period. Logout does not remotely revoke the external provider key; ask the instructor if revocation is needed.
- `course smoke`: check tool versions and actually build a sample PPTX and validate its LibreOffice PDF rendering without making a model call.
- `course boundary --mount PATH --resource FILE [--session SESSION_ID]`: run the existing facilitator-controlled boundary broker and capture its decision in the registered course session. The session argument is required when more than one course session is registered. The instructor supplies the mount and resource; this helper does not grant access. Direct broker commands remain visible in the Claude transcript but do not create a separate structured boundary stream.

Course credentials, adapter configuration, previous editor settings, capture state, and pending uploads are kept outside Git under `~/.local/state/course/<workspace-id>/`, with `0700` directories and `0600` configuration files. The adapter binds only to `127.0.0.1`, authenticates local requests, and is excluded from automatic Codespaces port forwarding. Its saved address remains stable across restarts. Logging in again stops the previous enrollment’s adapter before configuring the new one; logout or the course cutoff stops admissions and aborts outstanding adapter requests. The adapter also checks its cutoff independently of the capture watcher. The course password is never saved. A distinct `CLAUDE_CONFIG_DIR` is allocated per enrollment, and both CLI and extension receive it; personal `~/.claude` history is not scanned. Remote VS Code settings use `claudeCode.environmentVariables` because the extension checks this before launching its subprocess. They are private and explicitly excluded from Settings Sync. JSONC settings are accepted; original text is restored on logout when no intervening edit changed them.

Capture registers only newly started course sessions at the exact workspace root. It tails complete JSONL records, course subagent transcripts, referenced text tool-result files, and wrapper-generated boundary decisions. Symlink escapes and unrelated projects are excluded. Known inference, EIP, local-adapter, and upload credentials, plus recognizable credential/environment tool outputs, are redacted. This filtering is not a guarantee that arbitrary secrets pasted into prompts will be recognized: do not paste personal secrets. Binary or missing referenced attachments are represented by explicit omission markers. Records over 512 KiB become explicit capture-gap markers; referenced text artifacts are discovered incrementally from sanitized main and subagent records. These limitations are reported rather than represented as full tamper-proof capture.

Each queued chunk, its source offsets, and its sequence are committed together before upload. Failed uploads retry with backoff and jitter; only matching durable server receipts remove pending records. Restarting preserves collection authority and queues. The course collection cutoff or logout stops new collection, while previously captured records may flush until the server-issued upload expiry. Local course data is deleted after 30 days on the next watcher pass; deleting the Codespace earlier can lose unuploaded data. Client-controlled records can be altered or disabled and are not independent audit proof.

The container dependency hook uses the PPTX skill's lockfile, including `tsx` development dependencies. There are currently no additional course Python dependencies; the helper uses Python's standard library. `.student` activation covers tracked files and hidden directories, preflights collisions, skips generated output/dependency directories, and records a private rename journal for interrupted startup recovery. It never overwrites an existing destination. Resolve collisions deliberately before rerunning setup.

For a local smoke test, build with `docker build -f .devcontainer/Dockerfile -t course-student .` from a standalone clone, then mount that clone at `/workspaces/task` and run `course dependencies` followed by `course setup`. Use only synthetic enrollment data for integration tests; HTTP overrides via `COURSE_SERVER_URL` are accepted only for loopback addresses. No course secrets belong in the image, devcontainer configuration, committed settings, or prebuilds.
